# B — The listings: Leads (`/leads`) vs Projects (`/projects`)

Lead ↔ Project consistency audit, area B (2026-10-08). Read-only: a production build on :3011 over a scratch copy of the demo
data, Playwright at 1440×1024, 768×1024 (touch) and 390×844 (touch), Dane (Owner). Screenshots:
`scratchpad/lpaudit/shots/B/` — each finding has `B-nn-lead.png` / `B-nn-project.png`; the full pages are `page-{1440,768,390}-{lead,project}.png`.

**The standard** is the Leads listing (mock 1082:23305 and ~600 register rows), except where the register shows the owner chose
otherwise for Projects (REG-924…927, REG-1315, REG-1328, the build record `parity/23-…` §1) or the difference only exists because a
project holds different data. In three places the **Projects listing is the better pattern and Leads has drifted from its own
rules** (B-01, B-08, B-17) — said so in the row.

Shared already, measured equal: the L1 header (filled primary 36 · outlined second · ⋮ 36), the toolbar row (`ScopePill` 36,
the 280 DS SearchBar with "/", Filters with its count badge, `tune`, the segmented view toggle, "View all"), the table anatomy
(head 56, rows 64, cells p12/24/12/16 body-m, the name 14/700 turning primary + underline on row hover, hover `primary-variant`,
the frozen block's 1px edge, sideways scroll, resizable and draggable heads), the `BulkBar`, the `AssignPopover`, the
`ColumnSettingsDrawer`, the Filters shell (600×600, rail 160, Clear All · Done, live apply — REG-464), the `ExportDialog`
frame, "No results found" + Clear All, the phone card shell (Projects composes `lead-cards.module.css`).

## 2. Checked and fine

- **The tiles** (In progress · Needs attention · Waiting on client · Completing this month · Contract value) exist only on Projects — Q-06, REG-924. On a phone they take three rows above the list (fix-A, A-32) — decided.
- **Stage as a read-only tag** (outlined DS `Tag`, yellow Setting up, green In progress) where Leads has the stage menu (text + chevron): a project's stage moves by *Start the project* / *Complete handover*, never from a row (Q-03, REG-931); the Tasks table's STATUS uses the same tag for a status you don't pick there.
- **No kanban for projects; Workload instead** (Q-08 → REG-1328), and the toggle stays on a phone (REG-1328: "unlike the kanban").
- **No unseen band**: the band is "a new lead nobody has opened" (`seen_at`); projects carry no seen record.
- **Open projects by default, Completed hidden until asked** (Q-25). On hold as a scope (gaps build A, M-01).
- **Money**: "S$48,600" in the cell under "CONTRACT VALUE" matches the Quotes table's TOTAL; Leads' "BUDGET (S$)" with bare numbers is the lead mock's own head. Contract value / Collected / Margin for Owners and Admins only (Q-20, F-19).
- **Columns only projects have** (Number, Start date, Target end, Last activity as "2d ago", Next milestone, Progress, Last update, Collected) and **columns only leads have** (Tasks, Source, Budget, Property type, Created) — data.
- **The row menu's length** (10 rows with helps vs the lead's Open project · Delete · Return Lead): REG-925 "one set of items wherever the project appears" and the lead's mocked menu. Both say a refusal in the row (REG-728).
- **No hover Edit on a project row** (Leads: Edit + ⋮): a Won project's client details are its lead's; *Rename…* is in ⋮ and a direct project's details are edited from its Overview card (gaps build A).
- **First run**: the house `EmptyState` ("No projects yet", New project + Open Leads) vs the lead's mocked illustrated card (780:94126) — both carry their action and hide the toolbar (REG-735 ①–③; the checklist allows "the tab's own mocked card"). Not rendered (it needs an empty studio).
- **Filters' groups** differ by data (Leads: Quick filters · Property type · Source · Members · Date; Projects: Sort · Project type · Team); both apply live, Clear All · Done; Projects' Sort says when a head sort holds the order.
- **Column settings**: the same drawer, the identity column locked, 3 pins.
- **Header kebab** rows: Export all as… · Deleted … · … Settings on both (plus Lead Import History on Leads) — the Insights row is B-04.
- **Hover**: row fill, name colour and underline, the actions plate floating at the visible edge — identical.
- **Tickets (n)** in the Projects header — REG-1315 (see Q-1 for how it sits with Insights).
- **The project phone card's ⋮** — REG-377 ("the kebab stays"); the lead card has none because its mock has none.
