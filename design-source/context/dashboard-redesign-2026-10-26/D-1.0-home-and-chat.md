## 1 · 1.0's home as a layout

`/dashboard` is every role's landing in 1.0 (`getDefaultRoute`). DP decides between **chat-first** (the default) and **Classic**: the
choice is kept per browser in `localStorage["qanvast-home-mode"]` and set from Settings › Preferences › Home Screen ("Chat" / "Classic",
`settings/page.tsx:562` plg). On PLG, `/dashboard` is also where an anonymous visitor lands. The first send there opens a sign-up dialog
and keeps the typed question (CFH:494–525).

  to step aside (FAB:33).
- **The hero.** `pt-12`, the greeting at h2, and the composer at full width less 16 px gutters. The chips keep scrolling at 12 px with
  `py-2`. A tap pauses them only as a side effect of emulated mouse events, so **the chip you aim for moves under the thumb**.
- **The picker** is a dropdown under the chips, `max-w-sm`, eight results, with no keyboard or arrow navigation.
- **The widgets** are one column, and two from 640. Every widget is a whole-card link. **The rows inside look pressable (hover tints)

  card's Save / Share show permanently on touch (`sm:opacity-0 sm:group-hover:opacity-100`), but **Copy is hover-only, so it is invisible
  on a phone** (IR:221).
- **The type size.** 9–11 px for most widget text, with 3 px calendar dots.
- **Tablet** follows the `sm` / `lg` steps: two columns from 640 and four from 1024. There is no tablet-specific layout.

### 2.3 Capability chips and the entity picker (CFH:30–84, 567–598, 773–863)

- **The pool** is 12 chips, each an emoji plus a label: 📊 Studio overview · ✉️ Draft a follow-up · 🎯 What leads need attention? · 📋 Show my
  overdue tasks · 🔍 Analyze a lead · 💰 Optimize a quote · 📅 Plan a project timeline · ✅ Check compliance · 🏗️ Draft a site update · 🎨
  Generate a render · 👥 Team workload check · 💵 Revenue summary.
- **The marquee.** The pool is doubled and slides left forever in **30 s** (`chip-scroll`, `globals.css:1227`), with fade edges. It
  pauses on hover and while a picker is open. Global reduced motion stops it.
- **Two kinds of chip.**
  - A *prompt* chip sends a fixed question at once.
  - A *picker* chip (Draft a follow-up, Analyze a lead, Optimize a quote, Draft a site update) opens **"Select a lead to …" / "Select a
    project to update"**: a search field (focused) and up to 8 leads or projects, each with an initial avatar, the name and a second line
    (property type / client), plus Cancel. A pick **builds the prompt from the record's facts**, for example "Analyze lead Sophia Wong and
    suggest the best conversion approach (budget S$85,000, source: Qanvast)" (CHIP_PROMPTS, CFH:57–74).
- **The side panel's version** (BP:42–89, 959–977, 1105–1195) has 5 fixed chips with icons (Optimize Quote · Draft Follow-up · Analyze
  Lead · Generate Moodboard · Site Update). Its picker is a **bottom sheet inside the panel**. Its rows carry **a badge that fits the
  chip**: the lead's **quote status** for Optimize Quote (No quote / Draft / Submitted / Approved / Sent / Signed), the **style preference**
  for Generate Moodboard, the **stage** otherwise, and the project's stage for Site Update. Its list is active records only, newest first.

### 2.4 How an answer arrives

`useMaisonStream` posts to `/api/buddy/chat` and reads SSE events: `thinking` → `tool_start` → `tool_result` → `text_done` → `done`
(types.ts). The client shows the stages in this order (IR:847–960):

1. **Thinking dots**, plus the running tool's label ("Finance agent — loading studio financials...", IR:908–920).
2. **Tool status rows**: one per tool, a spinner while running, then ✓ with the tool's own summary and its time ("1.2s"). Once all are done
   they **fold into one green row, "3 tools completed · 1 failed ▾"**, which opens again on a press (IR:138–211).
3. **The cards** each tool's result asks for, above the text (§3.A).
4. **The text** in a bubble, rendered as markdown (headings, lists, **tables**, code). The server sends the whole text in one event, and the
   client **reveals it word by word** (3 words every 30 ms, with a blinking caret; `useTypewriter`, IR:721–755).
5. **The footer**: "✦ n tools", Copy (hover), and **"Continue conversation →"** once there are more than 2 messages. That last one hands the
   transcript to the side panel through `sessionStorage["maison-transfer-messages"]` (CFH:629–634, `(main)/layout.tsx:179–192`). **The
   panel does not draw the cards**: it shows only the status rows, doors, renders and charts (BP:344–644). The rich cards exist in the
   home's chat alone.
6. **The doors**, after the text (§3.A, A-11).

### 2.6 The tool layer: what produces the blocks

- **Model and loop.** `google/gemini-2.5-flash` through OpenRouter, **10 iterations** a turn, **67 tools** (`tools.ts`).
- **Status labels.** Each tool has an "agent" label, such as "CRM agent — fetching lead details...", "Chart Engine — rendering
  visualization...", "Opening tool..." (`TOOL_LABELS`).
- **Page context.** Each turn carries the page, the focused record, the view state and summary stats (`PageContextState`; the home sets
  `{ page: "dashboard" }`, DP:155).
- **Feature switches.** Tools are filtered by the studio's page visibility (`PAGE_TO_TOOLS`).
- **Writes.**
  - Leads, projects, tasks and member tags are **written at once with no confirm step**. PLG had to switch exactly these seven off
    (`WRITE_TOOLS`, `isPlgDeployment()`, page-tool-map.ts:47–72).
  - Finance writes are not in that list (create invoice, expense, PO, VO; record a payment or a delivery; approve an expense; review a PO;
    generate milestone invoices). They also run at once wherever Finance › Operations is on. The system prompt asks only "don't batch
    without user confirmation" for approvals (system-prompt.ts:789).
- **Limits and cost.** Rate limit 10 requests a minute per IP. **No credits are charged** for chat.
- **Charts.** The system prompt tells the model to **chain a data tool into `generate_chart`** for any "overview / breakdown / trend /
  forecast / how are we doing" question, and lists the chains: profitability → bar, cash flow → stacked bar, monthly revenue → line with last
  year, AR ageing → bar, expenses → donut (system-prompt.ts:596–665).

## 4 · What the redesign should bring across, ranked

All of these land on 2.0's rules: answers by rule today with the model behind `readQuestion`, **a change shown first with one button**,
every row a door with `?from=/dashboard`, house pieces, plain words, red only for late-and-ours, and motion only with a purpose.

1. **The docked composer that keeps the conversation on the page** (B-1 + A-18).
   - *Why:* it is exactly his "sticky like Claude's chat input". 1.0 had it, but only after a question, and only by replacing the whole home.
   - *Bring:* the composer pinned to the bottom of the Dashboard's content column on a desk, and above the dock on a phone. The answer
     opens **above it, in place**, in a panel that grows upward over the cards and folds back, so the cards stay underneath. Keep Stop,
     Retry, "↓ latest", "New question", Enter / Shift+Enter, and a growing field.
   - *Watch:* on the Dashboard this composer *is* Maison AI. Hide the FAB there rather than show two ways in. Recent is the history.
2. **Answers as cards, not paragraphs** (A-5 · A-6 · A-7 · A-8 · A-12 · A-13 · A-11).
   - *Why:* it cuts the wall of text he dislikes, and it is the most interactive thing 1.0's chat did.
   - *Bring, on house pieces, each with its door:*
     - a **tiles answer** (StatTiles, each a door: "Studio overview", "How is the studio doing?");
     - a **record card answer** (the lead's or project's own card: stage, next step, members, progress; "Tell me about Olivia");
     - a **timeline answer** (the Activity tab's day rows, the newest five, then "Open Activity");
     - a **small chart answer** (Reports' own figure for P&L, cash flow and revenue, with a tap tooltip; Reports stays the chart's home);
     - **progress rings** for a project's money only if Money adopts them;
     - **grouped doors** ("Open … · 4 ▾").
   - S10's `MaisonAnswer` (rows, share bars, link, plan) is the seed. Extend its block types rather than invent a second renderer.
3. **Chips that start a job, with a picker that knows the job** (B-4 + B-5, the panel's badges).
   - *Why:* one tap from "Draft a follow-up" to the right lead, with no typing. That suits an older owner on a phone.
   - *Bring:* 3–4 **still** chips by role beside the composer (no marquee, no emoji). The job chips open the house picker as a sheet on a
     phone, and each row shows **the fact that decides it**: the quote's status for "Check a quote", the stage and days since contact for
     "Draft a follow-up", the project's stage for "Site update". The pick answers through the existing house action, such as a draft that
     opens WhatsApp or the Updates composer.
4. **A receipt after a change** (3.G "Get work done" + A-1).
   - *Why:* 2.0 already proposes first. After the press, a row in the conversation that says what was done, with Undo, is the honest
     version of 1.0's "Record updated · Done".
   - *Bring:* the proposal card turning into a receipt row ("Task added — Call Olivia · Tue 3 PM · Undo · Open").
5. **A live status line for slow answers** (A-1 / A-2).
   - *Why:* a model answer takes seconds. 1.0's folded "n steps done ▾" is a good pattern; its words were not.
   - *Bring:* plain-words steps ("Reading your tasks…", "Adding up this month's invoices…") that fold to one line. Show it only past
     about 0.5 s, so today's rule answers stay instant.
6. **Unread conversations shown, each opening its own** (C-5).
   - *Why:* "who wrote and what" beats a count, and it is where 1.0 was most useful under the chat.
   - *Bring:* the Messages tile becomes up to 3 rows (face, name, last line, unread count), each opening that conversation (1.0's rows did
     not).
7. **A week strip instead of the month grid** (C-9).
   - *Why:* engaging and pressable. S22 rightly dropped a month of empty dots, but a 7-day strip with a dot per day that filters Coming up
     on a tap is real interaction over real dates.
8. **Bars where a comparison matters** (C-8 Team Workload, C-2 Leads, C-7 funnel).
   - *Why:* a bar reads faster than a sentence. Bring a capacity bar per member on Workload (2.0's projects-against-capacity rule) and

9. **The counts that name what needs a decision** (C-12 Contractors uhr, C-11 Response Time, C-3 Tasks chips).

   - *Bring:* the pattern for every tile: the figure, then one line or chip naming the item behind it, each a door.
10. **Photos on Site updates** (D-9).
    - *Why:* the photo is the update. A 40 px thumbnail from the update's own file (the house square thumb, REG-820).
11. **Voice and attachments on the composer** (B-2 · B-3).

12. **Save / Share on a picture answer** (A-15) for the day Maison AI answers with a render. Use the phone's share sheet.

## 5 · What 1.0 did badly: don't copy

- **The marquee**: 12 emoji chips sliding forever. It is motion without purpose, and a moving target under a thumb.
- **The page swap**: the first question hid the whole dashboard, and the transcript was lost on any navigation (no `persistKey`).
- **Three chats that disagree**:
  - the home's (rich cards, mic, attach);
  - the side panel's (no cards, no mic, its own chips and welcome, its own storage);
  - Classic's Business Performance Analyzer (non-streaming, no tools shown).
  "Continue conversation" moved you to the weaker one. **One assistant, one renderer.**
- **Writes with no confirm**: lead, project, task and member-tag changes, invoices, payments and approvals, done the moment the model
  chose to. PLG had to switch the first seven off. No receipt and no Undo after a write either. 2.0's propose-first stays.
- **Doors that land on a list**: Needs attention → `/leads`, the Upcoming rows (whose `route` was never used), the escalation rows,
  the unread rows. Every widget was a whole-card link with inner rows that looked pressable and were not.
- **Fake figures on a working page**: Classic's revenue $45,231, sample priority feed, donut, top clients, funnel; Today's Tasks
  toggles that saved nothing; an inert "+ Add task"; invented News stories under real newsrooms' names.
- **Numbers that drift from their home**:
  - Studio Pulse's previous week floored at 1, which inflates the %;
  - lead counts by bucket vs stage across branches;
  - Team Workload's task count of 0 for everyone (wrong id; fixed only on uhr);
  - the funnel's derived "invariants".
- **Model-invented data shown as fact**: the quote benchmark's "market typical", the meeting's "deal score".
- **Jargon**: "CRM agent — fetching lead details...", "Chart Engine", "3 tools", "Powered by mAIson AI" badges, "AI Powered".
- **Fake streaming**: a finished text revealed word by word.
- **Tiny type and targets**: 9–11 px text, 3 px dots, 24 px calendar days, Copy that only appears on hover (so never on a phone), the
  picker with no keyboard path.
- **A per-browser Home Screen setting** that made two homes to maintain (S22 already dropped it).
- **A stale design doc** (`docs/rules/dashboard.md` describes the reverted March redesign). Read the code, not that file.
