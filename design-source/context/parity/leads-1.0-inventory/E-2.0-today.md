## Decisions on record that constrain a 1.0 port

1. **The mock wins; nothing invented without a register row** (CLAUDE.md §1, REG-1…): any 1.0 behaviour with no 2.0 mock must be proposed first and logged as `user-directed` / `invented copy`; copy and data come from the lead's records, never from Figma or 1.0 samples (REG-403, no-mock-data rule).
2. **Stage vocabulary is fixed**: New · Contacted · Met · Quote Sent · Won · On Hold · Lost; "Manage Stages" is coming soon (REG-67, 115). Won is a stage, "Won" is not a close reason (audit row 210).
3. **Stage movement is a studio setting** — Linear (default) or Flexible — and every stage change goes through one dispatch (`stageIntent`); a new surface must not call `moveStage` directly (REG-111, 286; page checklist).
4. **Nothing moves backwards** — a completed stage opens read-only with Edit; kanban drops on earlier columns spring back; "Reopen Won / Lost" is a held question (REG-132, L-2).
5. **A lead needs an owner before it leaves New**; past New the last member cannot be cleared from the popover, the form or the New step (REG-130, 138, 231, 334).
6. **A Lost lead cannot jump to an unreached stage**; On Hold resumes anywhere with a "Resume at X?" confirm (REG-132, 225).
7. **Won always opens its step** (signed quote + contract + 100% split + project type) — even under Flexible (REG-111); Convert to Project = the Won step (REG-469).
8. **Stage details are mandatory** except remarks, the schedule pair and Met's documents; dates are pickers, never typed; numbers filtered at the keystroke; phones = 8 digits starting 6/8/9 (REG-118, 119, 150, 319, 543, 547).
9. **Deletes are soft with Undo and a Deleted sheet**; Delete Forever confirms; no Archive for leads (REG-28, 46–51, 264, 502).
10. **Assignment is many-to-many** (`lead_assignees`); a single-owner model would drop members (REG-231). Roles Owner · Admin · Manager · Designer and their reach are now on record (REG-601).
11. **Return Lead is Qanvast-only** and appears in every lead menu alike; one status vocabulary everywhere (REG-139, 200).
12. **The primary band = an unseen lead** (`seen_at`), not "newest"; every arrival lands unseen (REG-131).
13. **Contact logs live in one place**: the Move stage window is the source of truth for stage logs; the Notes tab derives them read-only; "Notes" fields are "Remarks" everywhere outside the Notes & Logs tab (REG-227, 265, 266, 267, 320).
14. **Demo data must be internally consistent** — every visible state needs its backing records (stage logs, `assigned_at`, quotes); seeding runs `npm run db:repair` then `db:baseline`; a new record type gets an Activity branch and a repair rule together (REG-343).
15. **Activity is derived, no event log** — anything 1.0 records as an event that leaves no row (removal, edit, deletion) will not appear unless an event log is built (REG-191, 335).
16. **Every list follows the listing's table model** (frozen first block, parked row actions, resizable heads, Column settings, live-apply filters, Done not Apply, uppercase heads, sort glyphs only on dates / amounts / status / names) and searches only what it shows (REG-274, 430, 454, 464, 468).
17. **One scope pill or Filters, never both for one dimension** (REG-297); the pill wears the applied dot off its default (REG-295).
18. **Modal scale s 400 · m 600 · l 800 · xl 1200 · xxl fluid; no full-page overlays**; the lead form does not dismiss on the scrim (REG-141, 321).
19. **Mobile mirrors the desktop's design language as a touch app**: ≤767 anchored surfaces are bottom sheets, tables are cards, 44px targets, nothing hover-only, level-1 pages only carry the bar + dock (REG-273, 312, 353, 362, 377).
20. **Every screen ships the shell** (rail, sticky header, ghost loader, tooltips, snackbar, Maison AI FAB via `AppShell`); inert affordances answer "Coming soon in OpenMaison 2.0" (REG-2, 507; page checklist).
21. **The signed-in member is always Dane (Owner)**; Manager / Designer views exist in code but the prototype has no sign-in (REG-286, 601).
22. **Quote lifecycle depends on Settings › Quotes › Quote approval**; a lead-side track must read `quoteStatuses(approval)` (REG-214).
23. **Meetings are hidden until their mocks land** (REG-552); calendar integration waits on them.
24. **Lead sources are a studio setting** with retire semantics — a port must not hard-code the enum (REG-599).
