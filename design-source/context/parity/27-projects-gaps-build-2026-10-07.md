Waves (two packages at a time — the machine is short of memory, builds one at a time behind a lock): **1** A + B · **2** C + E · **3** D.

**The contract between packages:** On hold = `projects.on_hold_at · on_hold_reason · on_hold_until · on_hold_by` + `lib/projects/hold.ts`
`holdOf` (A writes, D reads); a stage's `project_milestones.resolved_note · resolved_at` (C writes, D shows); compose from a milestone =
`/projects/{id}/updates?new=1&milestone={id}` (C links, D opens); bill when done = B's bell row + primary action, C's panel links
`/projects/{id}/money?open={invoiceId}`; files = E's storage, others file records as `lead_files` rows that open their page (`receiptOfFile`);
delivery = E's `lib/notifications/delivery.ts`. Shared files append-only.

**How it runs** (the projects build's recipe, refined): packages in worktrees under `.claude/worktrees`, synced from a bundle of MAIN's
uncommitted state (`sync.tar` + `deleted.txt`, no `git -C MAIN` from a worktree), a scratch DB each, one build at a time; they hand back a
final tree; the orchestrator merges file by file against the package's base tree (`merge.py`: take / three-way / conflicts listed), regenerates
one migration per wave, migrates and repairs local.db (backup first), numbers the register rows from REG-1168, re-runs every Projects probe.
Staged rows and outcome files: `projects-gaps-build/reg-<id>.md`, `<id>-outcomes.md`.
